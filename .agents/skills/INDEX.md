# Skills du portfolio

Cette bibliothèque locale conserve les skills utiles au projet dans un emplacement facile à retrouver : `.agents/skills/`.

## Animation et mouvement

| Skill | À utiliser pour |
| --- | --- |
| `animate` | Concevoir et implémenter une animation ou une interaction précise. |
| `gsap-scrolltrigger` | Piloter directement la progression d'une animation par le scroll : scrub, pin, parallaxe et déclencheurs. |
| `gsap-react` | Intégrer GSAP dans React avec `useGSAP`, refs et nettoyage au démontage. |
| `improve-animations` | Auditer les animations du projet et préparer un plan d'amélioration sans modifier le code produit. |
| `optimize-web-animations` | Mesurer et réduire le coût des animations, boucles, canvas et effets hors écran. |
| `fixing-motion-performance` | Examiner les problèmes de performances liés aux animations et au défilement. |

## Interface et qualité front-end

| Skill | À utiliser pour |
| --- | --- |
| `impeccable` | Concevoir, critiquer et affiner l'interface générale. Il couvre plus que les animations. |
| `create-design-md` | Documenter le système visuel confirmé du portfolio dans un `DESIGN.md`. |
| `improve-ui` | Auditer l'interface par rapport au brief et rédiger un plan de corrections, sans modifier le produit. |
| `react-best-practices` | Revoir la qualité des composants React après des changements dans plusieurs composants TSX. |
| `fixing-accessibility` | Vérifier l'accessibilité, le clavier, les formulaires, les contrastes et la réduction des mouvements. |
| `fixing-metadata` | Vérifier les métadonnées, les aperçus de partage et les informations SEO du site public. |
| `portfolio-verification` | Contrôler chaque livraison par rapport aux briefs et à la stack, inspecter le rendu, repérer les doublons et exécuter les vérifications pertinentes. |

## Contenus

| Skill | À utiliser pour |
| --- | --- |
| `humanizer` | Relire et rendre les textes du portfolio plus naturels, en gardant la voix de Gabriel et sans ajouter ni modifier de faits. |

## Règle d'utilisation

Ne pas charger tous les skills spécialisés pour chaque tâche. Choisir le ou les skills correspondant au travail demandé : conception, implémentation, audit, performance, accessibilité, métadonnées ou rédaction. Après chaque livraison de code ou d'interface, utiliser `portfolio-verification` comme revue transversale. Utiliser `humanizer` pour les textes destinés au portfolio, en préservant les informations validées et le ton choisi avec Gabriel. Pour les animations du portfolio, les références de style et de contenu restent celles définies avec Gabriel; les skills ne doivent pas remplacer ces décisions.
